# Daisy: план закреплённой загрузки моделей через GitHub Releases

**Статус:** готов к передаче разработчикам
**Дата проверки:** 23 июля 2026
**Решение:** начать только с Whisper. Раздавать публичные, неизменяемо именованные архивы из GitHub Releases. Не использовать Git LFS, платный object storage или автоматический fallback на Hugging Face. Parakeet и diarization пока не мигрировать: сначала подтвердить их продуктовую ценность отдельным A/B-тестом.

## 1. Цель и границы

Новая версия Daisy должна загружать модель Whisper не из Hugging Face, а из публичного репозитория Daisy на GitHub. Для каждого поддерживаемого варианта модель, URL и ожидаемый SHA-256 жёстко задаются в подписанном приложении.

Это даёт:

- воспроизводимый набор файлов для версии Daisy;
- контроль над тем, когда модель обновляется;
- проверку целостности до загрузки модели;
- отсутствие платной инфраструктуры.

В этот этап **не входят** Parakeet и diarization, перенос DMG/Sparkle, авторизация пользователя, аналитика скачиваний или R2. Они не являются заранее утверждённой фазой: решение о них принимается только после A/B из [`ASREngineEvaluation.md`](./ASREngineEvaluation.md) и отдельной проверки лицензий.

Модель всё равно физически отдаёт GitHub, поэтому в пользовательском тексте нельзя писать «скачивается только с серверов Daisy». Корректнее: «Daisy скачивает зафиксированный пакет модели из GitHub Releases; аудио при этом не покидает Mac».

## 2. Подтверждённые ограничения платформы

| Вопрос | Проверенный факт | Решение |
| --- | --- | --- |
| Цена | GitHub Releases не тарифицирует bandwidth и общий объём релиза. | Используем публичный Release, без платёжного аккаунта. |
| Размер | Один release asset должен быть меньше 2 GiB; до 1000 assets на релиз. | Перед релизом CI проверяет размер архива. Если архив turbo >= 2 GiB, его не публикуем до отдельного решения по разбиению/формату. |
| Git LFS | LFS имеет лимит bandwidth; при исчерпании без оплаты загрузки блокируются. | Git LFS запрещён для моделей. |
| Fair use | GitHub может ограничить или затроттлить чрезмерный трафик. | При текущем некоммерческом масштабе риск принимаем; это не гарантия/SLA. Мониторим жалобы и ошибки, но не строим платную инфраструктуру заранее. |

Источники: [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), [Git LFS billing](https://docs.github.com/en/billing/concepts/product-billing/git-lfs), [GitHub Acceptable Use Policy](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies).

## 3. Обязательный юридический gate

Публикация любого архива запрещена, пока для **точной версии и точного набора файлов** не завершена таблица лицензий ниже. Лицензия исходного Whisper сама по себе не разрешает автоматически публиковать чужую CoreML-конверсию.

| Артефакт | Текущий статус | Что должен сделать владелец релиза |
| --- | --- | --- |
| OpenAI Whisper weights | Предварительно зелёный: MIT допускает распространение при сохранении notice. | Положить MIT notice OpenAI в архив и в Third-Party Notices Daisy. |
| `argmaxinc/whisperkit-coreml`, конкретно используемая CoreML-папка | **Стоп до проверки.** У публичной CoreML-сборки нужно проверить `LICENSE_NOTICE.txt` и условия именно зафиксированного revision. Нельзя подменять её сборкой `whisperkit-pro`: у неё опубликовано proprietary notice, запрещающее распространение. | Зафиксировать URL + commit SHA, сохранить копию лицензии/notice в `licenses/`, получить письменное разрешение Argmax при неоднозначности. Если разрешения нет — не зеркалить; выбрать другую разрешённую сборку или воспроизводимо собрать свою. |
| NVIDIA Parakeet TDT v3 и Fluid CoreML-конверсия | Предварительно жёлтый: upstream и текущая карточка Fluid указывают CC BY 4.0. | Это не часть фазы 1. Перед фазой 2 проверить точный revision, весь набор вложенных моделей и выполнить attribution CC BY. |
| pyannote Community-1 и Fluid diarization CoreML | Предварительно жёлтый: карточки указывают CC BY 4.0; upstream также требует принять условия/передать контактные данные для получения файлов. | Это не часть фазы 1. До зеркалирования зафиксировать условия доступа, лицензии всех составных весов и attribution. |

Источники: [лицензия Whisper](https://github.com/openai/whisper/blob/main/LICENSE), [карточка Parakeet](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), [Fluid Parakeet CoreML](https://huggingface.co/FluidInference/parakeet-tdt-0.6b-v3-coreml), [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), [Fluid diarization CoreML](https://huggingface.co/FluidInference/speaker-diarization-coreml).

## 4. Репозиторий и модель релиза

Создать отдельный **публичный** репозиторий, например `DaisyApp/daisy-models`. Он содержит только скрипты упаковки, манифесты, лицензии и release assets; не содержит исходный код приложения, токены или пользовательские данные.

Для каждого опубликованного набора:

1. Тег: `modelset-whisper-<yyyy-mm-dd>-<short-source-sha>`.
2. Asset: `daisy-whisper-<variant>-<source-sha>.aar` либо другой один архив, подтверждённый integration spike.
3. Дополнительные assets: `manifest.json`, `SHA256SUMS.txt`, `LICENSES/` или архив с notices.
4. Все старые assets и теги хранятся бессрочно. Удаление/перезапись опубликованного asset запрещены.

`manifest.json` — документация и вход CI, но **не источник доверия в приложении**. Приложение хранит собственную копию следующих значений:

```text
model identifier / source revision / exact public URL / archive SHA-256 /
archive format / required free disk / required extracted layout
```

Тег, имя файла и URL не считаются доказательством целостности. Единственное техническое доказательство — SHA-256, скомпилированный в подписанный билд Daisy.

## 5. Реализация в приложении

### 5.1. Сначала короткий integration spike

До основной реализации разработчик должен на чистой машине взять существующую папку Whisper, упаковать её и подтвердить:

- точную ожидаемую WhisperKit структуру после распаковки;
- поддерживаемый архивный формат и сохранность всех `.mlmodelc`, tokenizer и `LICENSE_NOTICE.txt`;
- успешный `loadKit(..., download: false)` из распакованной папки;
- фактический размер default и high-accuracy вариантов (< 2 GiB на один asset);
- требуемое свободное место во время скачивания и распаковки.

Для SDK, поддерживающих Apple Archive, можно использовать `.aar`; актуальная документация Argmax описывает этот сценарий. Формат окончательно выбирается только по результату spike, не по предположению.

### 5.2. Downloader

Добавить `ModelSpec` для каждого варианта Whisper с полями из раздела 4. Поведение:

1. До скачивания проверить свободное место с запасом на архив, распаковку и служебные файлы.
2. Скачать в уникальную staging-папку вне активной директории модели. Поддержать системное возобновление загрузки после разрыва сети, если его даёт используемый downloader.
3. Посчитать SHA-256 **полного архива**. При несовпадении удалить staging-данные, один раз разрешить явный retry и никогда не распаковывать файл.
4. Распаковать в другую staging-папку, проверить обязательную структуру и наличие требуемых файлов.
5. Атомарно переместить завершённую папку в кэш моделей и записать локальный `installed.json` с идентификатором модели и проверенным SHA-256.
6. Только после этого вызывать загрузчик модели с `download: false`.

В нормальной работе не проверять сеть и не выполнять скрытый повторный download. При повреждённом кэше показать ошибку и кнопку явного повторного скачивания. Нельзя автоматически переключаться на Hugging Face: это нарушит заявленную предсказуемость источника и приватный UX.

Существующие пользователи: если старая модель успешно загружается, оставить её как есть и не принуждать к повторной загрузке. Она не считается ретроспективно проверенной SHA-256; все новые установки и явные повторные загрузки уже проходят новую проверку.

### 5.3. Публикация и supply chain

Скрипт упаковки должен быть закоммичен в `daisy-models` и создавать `manifest.json`, `SHA256SUMS.txt` и архив из зафиксированной исходной revision. В манифесте хранить:

- upstream repo, revision и URL;
- SHA-256 исходных файлов или исходной папки;
- версию конвертера/упаковщика;
- SHA-256 итогового архива;
- точный список файлов после распаковки;
- список включённых лицензий/attribution.

Перед публикацией релиза требуется peer review manifest и повторное вычисление хеша в CI. Права на публикацию assets — только у maintainer-аккаунтов. Это не заменяет хеш в приложении, но снижает риск ошибки при выпуске.

## 6. Тесты и критерии готовности

### Автоматические

- тест вычисления SHA-256 с корректным и изменённым архивом;
- тест, что URL, хеш и model identifier берутся только из `ModelSpec`, а не из удалённого manifest;
- тест валидации обязательной структуры после распаковки;
- тест атомарной установки: при ошибке загрузки/распаковки активная модель остаётся нетронутой;
- CI проверяет, что asset < 2 GiB, `SHA256SUMS.txt` совпадает с asset, а manifest соответствует архиву.

### Ручные на clean macOS account

- первая установка default Whisper и реальная транскрипция;
- high-accuracy вариант и реальная транскрипция;
- отсутствие сети после установки: модель работает и не обращается к сети;
- разрыв сети на 10%, 50% и 99%; повторная попытка не повреждает кэш;
- недостаточно свободного места: понятное сообщение до загрузки;
- намеренно повреждённый архив и распакованная модель: приложение не загружает их;
- существующий пользователь с кэшем от старой версии: нет обязательной перекачки;
- URL GitHub недоступен: видимый retry, без тихого обращения к Hugging Face.

### Definition of done

Фаза 1 завершена, когда все тесты выше пройдены, юридический gate для exact Whisper-артефакта зелёный, архив и notices опубликованы в публичном GitHub Release, а новый Daisy загружает и проверяет модель без обращения к Hugging Face.

## 7. Parakeet и diarization — не запланированы до A/B

Не нужно заранее писать собственный downloader для FluidAudio и не нужно переносить его модели на GitHub Releases. Исследование в [`ASREngineEvaluation.md`](./ASREngineEvaluation.md) рекомендует WhisperKit как default для встреч; FluidAudio сохраняет смысл только для быстрого Parakeet-диктанта и/или speaker diarization.

Отдельный PR допускается, только если:

1. A/B подтверждает Parakeet для диктанта по утверждённым порогам latency/WER; либо продукт явно сохраняет speaker labels.
2. Для точного набора FluidAudio/CoreML-артефактов пройден отдельный legal gate.
3. На закреплённой версии FluidAudio проверен штатный `ModelRegistry.baseURL` и `ModelHub.offlineMode`, чтобы исключить скрытый fallback к Hugging Face.

Если A/B не подтверждает выгоду Parakeet и Daisy отказывается от speaker labels, FluidAudio следует удалить, а не переносить.

Источник: [FluidAudio configuration](https://github.com/FluidInference/FluidAudio#configuration).

## 8. Последовательность работ

1. Назначить владельца legal gate; подтвердить exact Argmax CoreML лицензию письменно или сменить источник.
2. Создать публичный `daisy-models`, protection для main и правила публикации.
3. Провести Whisper packaging/load spike и зафиксировать формат, размер и disk budget.
4. Закоммитить воспроизводимый packaging script, manifest schema и notices.
5. Выпустить один тестовый modelset release, проверить архив и хеш из чистого клиента.
6. Реализовать downloader, atomic installation и UX ошибок в Daisy.
7. Пройти автоматические и ручные acceptance tests.
8. Выпустить Daisy с Whisper modelset; обновить Privacy/Third-Party Notices.
9. Только затем провести A/B и принять отдельное stop/go-решение по Parakeet и diarization; при go проверить `ModelRegistry.baseURL` и подготовить новый PR.

## 9. Явно принятые компромиссы

- Нет ежемесячных платежей и нет биллинга за модели.
- Нет SLA и нет автоматического резервного origin: GitHub outage временно блокирует новую установку модели, но не уже установленные модели.
- Нельзя удалять старые assets, иначе старые версии Daisy потеряют возможность восстановить кэш.
- При существенном росте трафика понадобится пересмотреть решение. Это будущая продуктовая/финансовая дискуссия, а не работа текущей фазы.
